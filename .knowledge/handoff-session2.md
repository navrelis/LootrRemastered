# Part 4: Reference

## Design in force (details in `decisions.md`)
- Integrated loot extends roll results, it does not rewrite tables. ## Known limitations so far
- Loot viewers read tables statically and do not show integrated extras.
- Bans check the top-level stack only; a banned stack a player put into their own Lootr inventory is also deleted; an item frame whose reference item is banned still displays it.
- The all-loot filter does not see stacks that other mods add after a table's own roll returned (CraftTweaker and Porting Lib loot modifiers, Aether); Lootr containers are still scrubbed.
- Config changes on a dedicated server need a restart.
- With loot seed 0 extras draw from the level random; the slot layout of an extended fill differs from vanilla for the same seed.
- Verification: `neoforge:conditions` are judged against Fabric mod ids (mods loaded through Sporran count as absent); one-slot holders are a fixed list; bans set through item functions are not seen statically; ban sources are called from the scan threads; three sample rolls cannot tell "rare" from "never" (tables without a container user are notes).
- Command feedback texts are hard-coded English; `lootr.commands.usage` omits newer sub-commands; `lootr.message.invalid_table` prints a ResourceKey instead of the plain id.
- Not planned: block entity sync requests still create one in-memory data object per asked container; `/lootr clear` skips data from before the opened flag existed; sticky menu builder; no feedback on a locked container; upstream issues #886 (double chests) and #788 (brush compatibility).
